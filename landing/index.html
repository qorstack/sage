The problem

Fast code is cheap. Wrong code is expensive.

Agents can produce plausible changes in seconds. The expensive failures happen before typing: missing context, invented patterns, and risks nobody named.

01 Context

Context gets skipped

The agent solves the prompt but misses the architecture, vocabulary, and decisions your team already made.

Sage loads the team’s rules and decisions first.
02 Reuse

Existing code gets reinvented

A new helper looks reasonable in isolation while duplicating a tested boundary that was already in the repository.

Sage reads real exports and patterns before adding more.
03 Risk

Risk stays implicit

Authorization, money, destructive operations, and public contracts need explicit controls—not confident prose.

Sage names the risk and stops only for decisions that matter.
04 Evidence

“Done” has no evidence

Agents report confidence where they should report validation output.

Sage requires the real build, test, or validation output and reports the residual risk.
How it works

A repeatable thought before every change.

The protocol turns good engineering judgment into a sequence any compatible coding agent can follow.

  2. 01
    Read

    Load the team’s context

    Use the role, rules, and decisions relevant to this change.

  3. 02
    Inspect

    Find what already exists

    Read the actual exports and patterns before proposing another.

  4. 03
    Judge

    Name risk and controls

    Restate the task and its done-criteria, then separate routine work from changes that need a human decision.

  5. 04
    Build

    Make the smallest coherent change

    Preserve contracts and keep the work inside the agreed scope.

  6. 05
    Prove

    Validate and remember

    Run real checks, report evidence, and capture durable knowledge.

The difference

The same agent. A better first move.

Sage does not replace your coding agent. It gives that agent a visible, reviewable operating discipline.

prompt→code

Without Sage

  • Starts coding directly from the prompt
  • Guesses internal APIs from filenames
  • Treats every unknown as an implementation detail
  • Reports confidence instead of validation output
prompt→thought→code

With Sage

  • Restates the task and what “done” means before coding
  • Reads the relevant team context first
  • Inspects reusable code before adding more
  • Stops only for decisions that genuinely change the outcome
  • Closes with evidence and residual risk
Install

Start in three steps.

One command installs the protocol. It adds the Sage protocol, command adapters, and knowledge structure for the coding tools you select.

  1. Run the installer in your repository

    bash -c "$(curl -fsSL https://cdn.jsdelivr.net/gh/qorstack/sage@latest/install.sh)"
  2. /sage-learning

    Run once to learn the project’s real patterns.

  3. /sage your task

    Then start each code change in plain language.

Workspace

One effort. One place to look.

Decisions, system design, implementation tickets, and focused evidence stay together under one durable flow workspace.
